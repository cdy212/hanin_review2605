1. 핵심 결론

최종 추천 내부 DB 리스트 우선, 관리자 등록, Place ID 저장, Google Maps URL 외부 이동 방식이 가장 비용 통제가 쉽습니다. Web 첫 화면에 Google Map을 바로 띄우거나, 앱에서 사용자가 자유롭게 업체 검색 API를 호출하는 구조는 비용 예측이 어렵습니다.
Web

지도 view를 바로 보여주면 Dynamic Maps map load 비용이 발생합니다. 기본은 리스트, 지도는 클릭 후 전환이 안전합니다.

APP

네이티브 Maps SDK 지도 자체보다 Places 검색, 상세, 사진, 영업시간 호출 비용이 리스크입니다.

저장 키

Map ID가 아니라 업체 식별용 Place ID를 저장해야 합니다. Place ID는 저장 및 재사용 가능하되 12개월 refresh 권장입니다.

Step 1 내부 DB 리스트

사용자 기본 화면은 내부 업체 리스트로 시작합니다.

Step 2 관리자 등록

업체 정보는 관리자 또는 업체 신청 기반으로 검수합니다.

Step 3 Place ID 저장

위치 연결에는 Google Place ID만 저장합니다.

Step 4 외부 Maps URL

지도 렌더링 대신 Google Maps 앱/웹으로 이동합니다.

Conditional 지도 보기 전환

지도 UX가 꼭 필요할 때만 lazy-load로 제공합니다.

Avoid Google Map 즉시 표시

Web page view마다 Dynamic Maps 비용이 발생합니다.

Avoid 사용자 자유 검색

반복 검색, bot, 오타 입력으로 Places 비용이 커질 수 있습니다.

Control Quota와 제한

검색을 열어야 한다면 서버 프록시와 횟수 제한이 필요합니다.

4. 개발 방식 옵션 검토

Option A. 내부 리스트 + Place ID + Google Maps URL 외부 이동

1순위

업체명, 카테고리, 지역, 소개, 영업시간, 이미지는 내부 DB에 저장하고, 위치 이동용 place_id만 저장합니다.

  • 일반 조회 시 Google 호출 없음
  • 관리자 등록/검수 때만 제한적으로 발생
  • 일반 사용자 조회 기준 비용은 $0에 가까움
https://www.google.com/maps/search/?api=1&query={업체명}&query_place_id={PLACE_ID}

Option B. 리스트 우선 + 클릭 시 Google Map 전환

2순위

기본은 내부 리스트, 지도 보기 탭/버튼 클릭 시 Google Maps JavaScript를 로드합니다.

  • 실제 지도 전환 사용자에게만 Web Dynamic Maps 과금
  • 지도 UX가 서비스 핵심일 때 적합
  • 월간 map view 예산과 quota가 필요

Option C. Google Map 금지 + OpenStreetMap/Leaflet

조건부

지도 view가 꼭 필요한 저비용 MVP라면 Web은 Leaflet, 지도 데이터/타일은 OSM 기반으로 검토합니다.

  • Google 비용 없음
  • OSM 공식 타일 서버는 SLA 없음
  • production은 타일 제공업체 또는 자체 호스팅 검토

Option D. 사용자 업체 자유 검색

비권장

사용자가 검색할 때마다 Text Search, Details, Photos 비용이 발생합니다. 반복 사용과 bot으로 비용 예측이 어렵습니다.

  • 로그인 사용자만 허용
  • 일/월 검색 횟수 제한
  • 서버 프록시, API key 비노출, quota hard cap 필요

5. “Map ID만 저장” 안에 대한 판단

정정 포인트 업체 위치 연결을 위해 저장해야 할 값은 Map ID가 아니라 Place ID입니다.
용어 의미 저장/활용 판단
Map ID Google Cloud에서 지도 스타일/설정과 연결되는 지도 식별자 업체 식별용 아님
Place ID Google Places 데이터베이스의 장소 식별자 업체 위치 연결용으로 저장 가능
googleMapsUri Place Details에서 받을 수 있는 Google Maps URL URL 자체가 Google 제공 콘텐츠일 수 있으므로 가능하면 Place ID로 URL 조립
내부 업체 ID 서비스 DB의 업체 record ID 반드시 별도 유지

7. 최종 추천 개발 방식

1차 MVP

  1. 업체 검색은 내부 DB 검색으로만 제공합니다.
  2. 업체 등록은 관리자 또는 업체 신청 기반으로 받습니다.
  3. 관리자 화면에서만 Google Place ID 조회/검수 기능을 제공합니다.
  4. 저장은 Place ID와 관리자/업체가 직접 입력한 업체 정보 중심으로 합니다.
  5. 리스트와 상세 화면에는 Google 평점, Google 리뷰, Google 사진, Google 영업시간을 기본 표시하지 않습니다.
  6. 위치 이동은 Google Maps URL 외부 이동 버튼으로 제공합니다.
  7. Web 첫 화면에 Google Map view를 렌더링하지 않습니다.

2차 기능

  1. 지도 UX가 필요하면 리스트 화면에 지도 보기 버튼을 추가하고 lazy-load합니다.
  2. 지도 view 사용량을 월 quota로 제한합니다.
  3. 사용자가 업체를 제안할 때는 검색 횟수 제한을 둡니다.
  4. 업체 제안은 곧바로 공개하지 않고 관리자 승인 후 내부 DB에 반영합니다.
  5. OSM/Leaflet 지도는 Google 비용 제거용으로 검토하되, production에서는 공식 OSM 타일 서버 의존을 피합니다.
