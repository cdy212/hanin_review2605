# 항목 정책 답변
1
회원 인증 방식
이메일 / 휴대폰 / 회원명부 / 관리자 승인 / ARC 등

정회원 / 기업회원 → 한인회 관리자 수기 인증

  • 일반 회원 가입 후, 관리자가 수동으로 정회원/제휴회원 인증 처리.
  • 인증 대상: 한인회비 납부자 / 후원자 / 기타 (한인회 내부 기준 적용)
  • 인증에 필요한 내부 기준 정보 및 확인 항목은 추가 정의 필요.
2
ARC / 신분증 자료 보관
인증 후 삭제할지, 보관할지 확인 필요

보관하지 않음. 인증 후 서버에 저장하지 않습니다.
3
업체 등록 방식
한인회 직접 등록 / 업체 신청 / 한인회 승인 후 등록

업체 직접 신청 → 한인회 관리자 승인 후 등록

  • 메인 상단 플로팅 배너 '업체 등록' 버튼 노출 → 혜택/정책 게시물로 이동.
  • 기입 항목: 업체명대표사진업체주소연락처첨부파일
  • 관리자 확인/승인 후 등록 완료. (kr.happytuk.tw/main)
4
할인 QR 이용 방식
QR 스캔 / 기록 저장 / 회원정보 범위 확인 필요

QR 보류 → PIN 번호 방식으로 대체

  • 업체가 쿠폰 등록 → 사용자 개별 다운로드 → 업체에 PIN 입력하여 사용 처리.
  • 사용자는 쿠폰 1인 1개만 발급. 발급/사용 이력 확인 가능.
  • 발행권한: 기업회원 이상 / 사용권한: 정회원 이상 (일반회원은 목록만 조회)
  • 사용 이력 엑셀 다운로드 기능 추가 예정.
5
업체가 확인 가능한 회원 정보
유효 회원 여부만 표시할지 확인 필요

사용자가 쿠폰을 업체에 직접 공유 → 업체가 PIN 입력으로 사용 처리.

  • 별도 회원 정보 확인 없음. 업체는 회원 개인정보에 접근하지 않습니다.
6
위치정보 사용 여부
주변 업체 찾기 기능에서 위치정보 사용 여부

위치 정보 사용. 주변 업체 찾기 기능에서 사용자 위치정보를 활용합니다.
7
자유게시판 운영 방식
작성 권한, 신고, 삭제, 정지 처리 방식
  • 작성권한: 정회원 이상 / 구인구직: 2주에 1회 제한
  • 신고: 3회 누적 시 자동 숨김 → 관리자 확인 후 숨김/삭제 처리.
  • 사용자 제재: 관리자 수동 처리, 제재 등급 3일/5일 차단.
  • 제재 후 로그아웃 → 재로그인 시 '소명 알림 팝업' 노출 → 관리자 검토 후 최종 처리.
8
개인정보 수집 및 보관
수집 항목, 보관 기간, 삭제 방식

  • 기업회원: 회사명대표자명회사 주소연락처이메일
  • 삭제: 탈퇴 신청 후 30일 경과된 사용자에 한하여 삭제 처리.

# 2차 확인 필요 항목 (PDF) 확인 세부 내용 (정책/약관) 실제 koreaTaiwan 프로젝트 구현 현황 & 대응 방향
1
푸시 기능의 「소식」의 범위
푸시 알림 수신 대상 및 홍보성 정보 포함 여부
  • 공지/서비스 알림: 한인회 공지, 주요 행사, 서비스 기본 알림 포함 여부 명시.
  • 홍보성 정보: 업체 혜택, 쿠폰, 제휴 행사 등 마케팅/홍보성 정보 포함 여부 확인 필요.
  • 약관 반영: 서비스 알림과 마케팅/홍보성 알림 수신 동의 항목 분리 수집 필요성 검토.
koreaTaiwan 실제 구현 현황
  • expo-notifications 및 WebPush (firebase-messaging-sw.js) 연동 완료.
  • 현재 푸시 카테고리(공지 vs 마케팅/혜택)별 수신 동의 선택 분기 UI 미구현 상태.
  • 대응: 마케팅 정보 수신동의 별도 동의 항목 추가 및 약관 내 수신 목적 구체화 필요.
2
쿠폰 이용 기록 엑셀 열람 범위
역할별 엑셀 열람 권한 및 포함 항목
  • 열람 주체: 관리자만 가능 / 쿠폰 발행 기업회원 가능 / 양쪽 모두 가능 여부 확정.
  • 역할별 범위: 제휴업체는 자사 쿠폰 사용건만 열람, 관리자는 전체 열람.
  • 다운로드 항목: 회원 식별자(마스킹 여부), 쿠폰명, 사용일시, 할인 금액 등 실제 추출 필드 확정.
koreaTaiwan 실제 구현 현황
  • 제휴업체/관리자 쿠폰 관리 API (/api/v2/coupon/manage/list) 및 목록 화면 구현 완료.
  • 프론트엔드 내 엑셀 추출(CSV/XLSX) 다운로드 기능 버튼은 백엔드 추가 연동 대기 상태.
  • 대응: 백엔드 엑셀 다운로드 API 스펙 정의 시 마스킹 정책(이름/연락처) 준수 필요.
3
회원 탈퇴 방식 & 유예 기간
신청 경로, 30일 보관 기산점, 철회 기능 여부
  • 신청 경로: 앱 내 탈퇴 접수 경로 및 처리 방식 확정.
  • 30일 보관 기산점: 탈퇴 신청일 기준 30일 유예 보관 후 파기.
  • 계속 보관 자료: 30일 경과 후 법령/운영상 보관되는 자료(쿠폰 사용 이력 등) 범위.
  • 유예 기능: 30일 내 탈퇴 신청 철회 기능 제공 여부 및 신청 후 30일간 앱 이용 가능 여부 확인.
koreaTaiwan 실제 구현 현황
  • app/(views)/setting/withdraw.js 및 components/withdraw/index.js 구현 완료.
  • 동의 체크 후 '탈퇴' 키워드 입력 시 /auth/withdraw (또는 /social/withdraw) API 호출 및 즉시 로그아웃 처리 구조.
  • 대응: 현재 즉시 탈퇴 처리 방식임. 30일 유예기간/철회 도입 시 백엔드 유예 상태 및 프론트엔드 철회 안내 UI 개발 필요.

수집 자료 및 시스템 기록
자동 생성 자료 항목 & 회원 인증 첨부파일 종류
  • 자동 생성 자료: IP 주소, 기기 모델/식별 정보, OS, 로그인/이용 기록, 오류 기록, 보안 로그 등.
  • 인증 첨부파일: 회원/업체 인증 신청 시 업로드 요구 자료 유형 (ARC 사진, 사업자등록증, 업체 증명 서류 등).
  • 보관/파기 정책: 증빙 서류 확인 후 즉시 파기 여부 약관 명시.
koreaTaiwan 실제 구현 현황
  • components/terms/privacy.js에 IP 주소, 쿠키, 서비스 이용기록 자동 수집 문구 포함.
  • 제휴업체 등록(components/store/manage/index.js) 시 대표사진 및 사업자/증빙 파일 업로드 기능 구현됨.
  • 대응: ARC/증빙서류 확인 즉시 파기 방침 약관 및 개인정보 처리방침에 명확히 명시 필요.

  • 대상 항목: 쿠폰 이용 기록, 위반/제재 기록, 로그인/보안 기록, 고객 문의 기록, 기업/업체 심사 기록.

주변 업체 찾기 실시간 처리 및 서버 저장 여부

  • 서버 저장 여부: 위치정보를 서버로 전송/저장하는지 여부 및 저장 시 보관 기간 지정.

  • 앱/웹 화면에서 내 위치 버튼 클릭 및 지도 조회 시 단말기(Foreground)에서만 위도/경도를 실시간 수집 후 거리를 계산(getDistance).
