# 한인회 E2E 재실행 지침

사용자의 추가 요청에 따라 별도로 저장한 지침이다. 2026-10-04의 문서 작업과 분리해 새 E2E run을 시작할 때 사용한다. 이전 PASS와 캡처를 새 run의 증빙으로 재사용하지 않는다.

## 1. 재실행 준비

1. 00_progress.md, AI_QA_WORKFLOW.md, QA_CASES.md, FINDINGS.md와 저장소 지침을 읽는다.
2. F(사용자 웹), A(백엔드 및 운영 콘솔), DB 종류, 역할별 테스트 계정을 확인한다. qa 설정은 koreans.tw이고 test 설정은 LAN IP다. development만 로컬 7777이다.
3. 새 runId `QA_YYYYMMDD_HHMM`을 만든다. U 신규 2명(REGULAR/PARTNER 신청용), R 정회원, P1/P2 제휴업체, O 운영자 세션을 준비한다. 비밀번호·토큰은 결과 파일에 저장하지 않는다.
4. git status와 commit을 기록하고 기존 변경을 보존한다. 운영자 CMS의 기존 활성 수량 등 baseline을 읽기만 한다.
5. DB 대상 미확정/계정 불가이면 BLOCKED로 기록하고 공개 화면 검사만 한다. 승인된 쓰기 환경을 확보한 뒤 사이클을 이어간다.

## 2. 로컬 실행

```powershell
# 프론트 폴더: app/koreaTaiwan. 기존 포트 프로세스를 임의 종료하지 않는다.
$env:EXPO_PUBLIC_APP_VARIANT = 'development'
& .\node_modules\.bin\expo.cmd start --web --port 8088
```

백엔드는 LOCAL_TEST_GUIDE.md에 따라 환경 식별·VPN/DB 접근 확인 후 `run-local-qa-db-20260827.cmd`를 사용한다. 보호된 properties 파일을 열어서 환경을 알아내지 않는다. Hikari/JPA/Tomcat 완료와 7777 LISTEN까지 확인한다. 실제 로그인 시 본문 로깅에 민감 정보가 남지 않는 실행 구성을 담당자와 확인한다.

```powershell
Get-NetTCPConnection -State Listen -LocalPort 7777,8088 -ErrorAction SilentlyContinue
```

`start-test.ps1`은 mock 세션과 LAN API를 사용한다. 실제 로그인/권한/승인/쿠폰 E2E에는 사용하지 않는다. 현재 화면 증빙용 관리자 정적 서버는 다음과 같다. 이 서버는 실제 운영 콘솔 기능 테스트를 대신하지 않는다.

```powershell
python app\docs\final-qa\serve_admin_preview.py
```

## 3. 재실행 순서

1. TC-AUTH: 로그인·회원가입 폼·약관·비로그인 가드. TC-SIGNUP-01~07로 일반 신규 가입→운영 users 조회→첫 메인/프로필→재로그인을 수행한다. TC-SOCIAL-01~09는 Google·카카오·네이버별 신규 가입→운영 조회→중복 가입 거절→기존 계정 로그인과 취소/실패를 확인한다. 신규 QA 수신함·제공자 계정과 플랫폼별 승인 callback을 먼저 준비한다. AUTH-06/08은 상세 케이스 증빙을 참조하고 별도 회원을 중복 생성하지 않는다.
2. TC-MAIN: 운영자 TOP 배너·중앙 아이콘 생성→사용자 메인→링크→수정→비활성/삭제→사용자 재조회.
3. TC-MEM: 일반회원 REGULAR/PARTNER 신청→운영자 대기 검색→반려/수정/승인→사용자 재로그인과 역할 확인.
4. TC-STORE: 승인된 제휴업체가 한인맵 + 모달로 업체 등록→본인 관리→일반 사용자 검색/상세→수정→타 업체 권한 거부.
5. TC-COUPON: 업체 쿠폰 생성→운영 목록→정회원 받기→내 쿠폰→잘못된 PIN→정상 사용→재사용 실패→운영 사용 내역. LIMITED/PERSONAL/만료·숨김/일반회원 거부는 새 데이터를 따로 사용.
6. TC-USER: 커뮤니티·댓글·좋아요·북마크·신고/운영 숨김, 프로필·지역·알림·제재/소명. 탈퇴는 일회용 계정만 마지막에 실행.
7. 이번 runId 데이터만 정리하고 재조회한다. 이미 사용한 쿠폰/감사 이력은 정책에 맞춰 보존한다. 정리 실패도 결과에 기록한다.

각 TC의 상세 절차와 기대 결과는 QA_CASES.md에 있다. 해당 문서는 하나의 기능에서 관리와 사용자 확인이 끝나도록 구성했다. 모든 관리자 기능을 먼저 바꾸고 나중에 사용자 화면을 몰아서 확인하지 않는다.

## 4. 통과 판정과 캡처

| 확인 | PASS 조건 |
|---|---|
| UI 조작 | 빈 화면/크래시/무한 대기 없이 행동 가능 |
| 요청 | 해당 작업의 실제 method/path/status가 기대에 부합 |
| 저장 | 재조회에 동일 ID와 변경 내용 유지 |
| 사용자 연동 | 반대 역할 화면에서 같은 데이터·상태 확인 |
| 실패 케이스 | 기대한 안내/차단, 데이터와 카운트 미변경 |

성공 토스트만으로 PASS를 주지 않는다. 캡처에는 로그인 비밀번호, 직원 PIN, 인증 헤더와 개인 정보가 없어야 한다. URL·TC ID·행동·Expected·Actual·판정·증빙 파일명을 남긴다.

가입 캡처: 가입 폼/동의, 인증 완료 안내, 가입 후 메인/프로필, 운영자 회원 조회, 로그아웃 후 재로그인, 중복/취소 안내. 인증번호·메일주소·OAuth code/state·제공자 개인 프로필은 노출하지 않는다. 웹/네이티브 결과를 별도 기록하고, 이전 가입 폼 캡처를 실제 가입 완료 증빙으로 사용하지 않는다.

| TC-MAIN-01 | O 관리자→U 메인 | 신규 배너 노출·링크 이동 | 실행 후 기록 | NOT_RUN | 실행 후 기록 |

## 5. 중단 후 이어가기

TC 전후 진행파일 저장. 사용량 제한이나 세션 종료 시 다음 행동을 한 문장으로 명확히 적는다. 재개 시 먼저 현재 데이터 상태를 조회하고 중복 신청·다운로드·사용 요청을 방지한다. 매시간 후속 자동화는 최신 진행파일을 읽어 재개하며 작업 완료 뒤 중지한다. 환경/계정 질문이 미해결이면 운영 쓰기로 우회하지 않는다.

## 6. 이번 작업에서 실제 사용한 방식

Expo development 로컬 8088, CUA 브라우저 읽기 검증, Python 8090 관리자 정적 소스 제공, JPG 화면 증빙. 브라우저 전담 서브에이전트는 E2E 스킬의 위임 단계에 따라 사용했다. 현재 환경에는 스킬에 적힌 ask_question/browser_subagent라는 이름의 도구가 없어 비동기 질문과 collaboration/CUA로 같은 역할을 수행했다. 실제 결과·확인 범위는 BROWSER_QA_REPORT.md에 남긴다.
