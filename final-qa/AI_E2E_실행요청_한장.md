## 그대로 전달할 실행 요청문

한인회 **LIVE에 배포된 서비스**를 https://koreans.tw 기준으로 브라우저 E2E 테스트해줘. 로컬 소스는 동선·기대값 참고로 사용하고 배포 버전과 일치하는지는 별도 확인해줘. 계획 제시에서 끝내지 말고 아래 범위에서 실행 결과와 증빙을 저장해줘.

1. **지침 읽기:** 프로젝트 지침과 `app/docs/final-qa/00_progress.md`, `AI_QA_WORKFLOW.md`, `E2E_RETEST_GUIDE.md`, `QA_CASES.md`, `SOURCE_MAP.md`, `FINDINGS.md`를 읽어라. 이번 run은 LIVE 모드다. 기존 문서의 F/A를 위 LIVE 주소로 치환하고, 로컬 서버 실행 절차는 적용하지 마라. 최종 웹 URL·실제 API origin·확인 가능한 배포 버전과 점검 시각을 기록해라.
2. **실행 조건:** LIVE의 지정된 QA 계정·테스트 데이터만 사용하고 실제 회원·업체·쿠폰·기존 공개 CMS를 변경하지 마라. 메인 CMS 공개 노출 변경은 LIVE에서 허용된 항목·시간·복구 범위를 먼저 확정해라. 메일/푸시는 지정 QA 수신함/기기에만 보내라. 실제 웹 진입 경로·계정·허용 데이터가 미확정이면 가능한 공개 검사를 수행하고 필요한 조건을 BLOCKED로 기록해라. localhost·8090 정적 미리보기·mock 성공으로 LIVE 테스트를 대신하지 마라.
3. **브라우저 실행:** 사용 가능한 실제 브라우저 자동화 도구로 UI를 조작해라. 역할별 세션을 분리하고 새 runId `QA_YYYYMMDD_HHMM`을 만들어라. API 호출은 보조 증거로 사용해라. 로그인·MFA·CAPTCHA 등 사용자 조작이 필요한 단계는 넘기지 말고 해당 단계에서 인계해라.
4. **기능별 한 사이클:** 일반 가입(이메일 인증→가입→운영 회원 조회→첫 메인/프로필→재로그인), Google·카카오·네이버 신규 가입/기존 로그인/중복/취소, 운영자 CMS→사용자 메인, 정회원·제휴 신청→운영 승인→재로그인, 업체 등록→사용자 지도, 쿠폰 생성→받기→사용→재사용 거절→운영 내역, 나머지 사용자 기능 순서로 진행해라. 상세 TC와 실패 조건은 QA_CASES를 따라라. 웹 성공을 모바일 성공으로 합산하지 마라.
5. **통과 기준:** 실제 UI 동작, 같은 ID의 저장·재조회, 상대 역할 화면 반영, 새로고침/재로그인 유지와 대표 실패 조건까지 확인해야 PASS다. 소스 분석·화면 렌더·HTTP 200·성공 토스트만으로 PASS를 주지 마라. 관찰된 불일치는 FAIL, 실행 조건 부족은 BLOCKED로 구분해라.
6. **결과 저장:** `app/docs/final-qa/runs/{runId}.md`에 TC ID·역할·URL·절차·Expected·Actual·판정·데이터 ID·증빙 경로를 기록해라. 민감정보 없는 스크린샷을 screenshots에 저장하고 QA_CASES, 운영자 매뉴얼, FINDINGS, 00_progress를 갱신해라. 비밀번호·PIN·토큰·인증번호·OAuth code/state·개인정보·민감 설정 파일을 기록하지 마라.
7. **중단·재개:** 각 TC 전후에 마지막 완료 단계와 다음 행동을 저장해라. 재개할 때 생성된 회원/신청/발급/사용 상태를 먼저 조회하여 중복 요청을 방지해라. 기존 자동화 `qa`를 중복 등록하지 마라. 사용량 제한 후에는 실행 가능한 시점에 기록부터 이어가고, 크레딧 구매나 제한 우회를 하지 마라.
8. **종료:** 이번 run의 허용된 데이터만 정리하고 실제 PASS/FAIL/BLOCKED와 사용자 조치 사항을 짧게 보고해라. 결함을 임의로 수정·커밋·배포하지 마라. 전체 요청 범위가 완료되면 기존 후속 자동화를 중지해라.

주소 근거: `app/koreaTaiwan/app.config.js`의 production apiUrl은 https://koreans.tw다. LIVE의 웹 라우트·현재 배포 버전·신규 가입/연동 성공은 이 문서 작성에서 검증하지 않았다. 기존 localhost 화면 증빙은 LIVE PASS로 재사용하지 않는다.
