# 소스 기반 최종 QA 실행 계획

요청 범위: 기능 단위 운영자→사용자 연결 검증과 운영자 매뉴얼, AI QA 지침·재개 기록, 별도 E2E 재실행 지침.

1. 현재 프론트/백엔드 commit 및 미커밋 변경을 기록하고 현재 소스에서 화면·API 연결표를 추출한다.
2. 메인 CMS, 정회원 승인, 제휴 승인, 업체 등록, 쿠폰 등록→발급→사용, 사용자 커뮤니티/마이페이지/설정 순서로 사이클을 설계한다.
3. 로컬 development 프론트를 8088에서 실행한다. 백엔드·DB 대상이 확정되지 않은 상태에서는 공개 화면·인증 가드만 확인한다.
4. 관리자 정적 소스를 localhost:8090에 제공해 로그인·양식의 구조를 캡처한다. 이 화면은 DB 없는 템플릿 미리보기이며 운영 기능 성공 증빙으로 사용하지 않는다.
5. 실제 연결 환경/역할별 테스트 계정이 확보되면 각 TC를 UI로 실행하고 요청 성공과 재조회, 반대 역할 화면, 새로고침 후 상태를 함께 확인한다.
6. 스크린샷, 실행 결과, 결함 후보, 미실행 이유를 기록하고 문서의 로컬 링크·파일 근거를 점검한다.

완료 기준: 문서 패키지 작성 완료와 실제 E2E 통과를 별도 판정한다. 관리자 성공 메시지나 HTTP 200만으로 완료하지 않는다. 사용자 화면에 같은 데이터가 반영되고 상태가 유지되어야 해당 TC를 PASS로 처리한다.

현재 사용자 요청에 따라 소스 분석과 로컬 읽기 검증은 바로 진행한다. 운영 도메인이나 식별되지 않은 DB의 쓰기 테스트는 테스트 대상 확인 후 수행한다.
