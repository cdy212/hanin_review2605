1. 개발팀 작업 진행 방식 결론

  1. 기본 화면은 내부 DB 기반 업체 리스트로 구현 사용자가 업체를 조회할 때 Google Places API를 실시간 호출하지 않고, 서비스 DB에 저장된 업체명, 카테고리, 지역, 소개 정보를 먼저 보여줍니다.
  2. 업체 등록은 관리자 또는 업체 신청 후 승인 방식으로 처리 Google 검색 결과를 사용자 화면에서 바로 노출하지 않고, 관리자 검수 또는 업체 신청 데이터를 내부 DB에 확정 저장합니다.
  3. 업체 위치 연결값은 Map ID가 아니라 Place ID를 저장 업체 식별과 Google Maps 이동에는 Place ID를 사용하고, 서비스 내부 식별자는 별도 vendor_id로 관리합니다.
  4. 지도는 화면 내 렌더링보다 Google Maps URL 외부 이동을 우선 적용 MVP에서는 Web 첫 화면에 Google Map을 바로 띄우지 않고, 위치 버튼 클릭 시 Google Maps 앱 또는 웹으로 이동하도록 구현합니다.
  5. 이미지, 영업시간, 전화번호는 자체 입력값을 사용 Google Places Photos, 영업시간, 전화번호를 목록/상세에서 매번 호출하지 않고, 관리자 또는 업체가 입력한 값을 기준 데이터로 사용합니다.
  6. Google API는 관리자 등록/검수 화면에서만 제한적으로 사용 Place ID 조회, 위치 검수 등 운영자용 기능에 한정해 호출하고, 일반 사용자의 자유 검색 기능은 MVP 범위에서 제외합니다.
  7. 지도 보기 기능은 2차 기능으로 분리 실제 사용성 검증 후 필요할 때만 리스트 화면에 지도 보기 버튼을 추가하고, 클릭 시점에만 Google Map을 로드합니다.
  8. 사용자 업체 제안은 로그인, 횟수 제한, 관리자 승인 플로우가 갖춰진 뒤 진행 반복 검색, 오타 검색, 자동화 접근으로 비용이 커질 수 있으므로 검색 기능 개방은 별도 예산 승인 후 적용합니다.

2. 비용 산정 기준

판단 현재 문서의 핵심 비용 수치는 Google Maps Platform의 무료 사용량 cap을 먼저 차감한 뒤 유료 호출분만 계산한 값입니다.
산정 기준

월 예상 비용 = max(월 호출량 - 무료 사용량, 0) / 1,000 * SKU 단가를 기본으로 사용했습니다.

복합 시나리오

Web처럼 검색과 지도 view가 함께 발생하면 Places 비용 + Dynamic Maps 비용을 합산했습니다.

주의 사항

검색 결과 20개 전체에 상세와 사진을 붙이는 구조는 호출량이 검색수 * 20으로 커져 MVP에는 부적합합니다.
